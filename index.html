03 / How I work

Three habits you'll notice in the code.

They're not values on a wall. Each one shows up in the projects above — especially in the boring parts that keep a demo alive.

01

Own the whole slice

Schema, API, UI, deploy. I'd rather finish one feature end to end than start five and hand over a pile of half-wired branches.

02

Make it survive review

Seed data, demo modes, snapshot fallbacks. If a recruiter clicks a link at 11pm, it should still work — not show them a stack trace.

03

Write the README

Setup steps, architecture, trade-offs, what I'd do next. If someone else can't run it, it isn't finished.
